# JEV 연결: 번역 분류·게임 선택

2026-09-30 사용자 요청으로 TypeSafe JEV API를 설정했다. 게임 진행 파일럿과 Codex 토큰 절감도 요청되어 캡처 하네스에 제한된 선택 연결을 추가했다. 최신 지시에 따라 Codex 사용량은 중단 기준으로 쓰지 않는다. RAM/swap은 실행 전후 수동 확인하고, 디스크 보존량은 하네스가 자동 검사한다.

JEV는 자유로운 번역문 생성 대신 질문별 확률/선택/점수를 반환한다. 이 프로젝트에서는 번역 의미 오류 후보 분류와 게임 파일럿에서 미리 정한 행동 후보 중 선택하는 데 쓴다. 인코딩·포인터·행폭·글리프 검사는 기존 로컬 도구가 수행한다. 낮은 오류 확률은 QA 통과나 배포 승인이 아니며, B팀 보호 문구나 번역 파일을 자동 변경하지 않는다.

## 게임 선택 파일럿과 Codex 토큰 절약

`tools/playthrough_capture.py`에 입력하는 `jev temp/...json` 명령은 현재 체크포인트에 결합된 후보를 JEV에 한 번 질의한다. JSON `state`의 `observed_rom_sha256`, `observed_frame`, `checkpoint_sha256`, `frame_image_sha256`가 실행 중 캡처와 정확히 일치해야 한다. 체크포인트 SHA는 `.checkpoint.json` 파일 자체의 SHA-256이다. 바인딩은 **증거 파일의 신선도만** 확인하며, 유닛·HP 같은 기술된 게임 상태와 실제 에뮬레이터 상태의 일치는 자동 검증하지 않는다. RAM/swap은 실행 전후 수동 확인한다. 하네스는 설정 기본값인 디스크 여유 10GiB 미만에서 프레임 전에 멈추며, JEV 호출 전에도 같은 검사를 한다. 세션 시작 시 새 이미지 증거를 남길 중립 프레임 1개가 진행된다. 후보 ID는 `c0`~`c7`; 단계는 `inspect` 또는 `commit`이다. 입력은 로컬 `inputs` 배열로만 정하며 API에는 보내지 않는다. 자동 매크로는 inspect에서 방향키/NONE만 허용하며 최대8단계·480프레임이다. 화면 기반 합법성 검증기가 없어 commit 입력은 항상 수동으로 남긴다. 신뢰도와 선택 확률 기준(inspect 0.5, commit 0.7), 확률합·선택여유 검사는 보정 전 파일럿 정책이다. 한 Recorder 프로세스에서 최대8회이며 API 호출 시도(실패 포함)가 횟수에 포함된다. 같은 요청 해시는 한 Recorder 세션에서 재전송하지 않는다. Recorder와 독립 CLI는 추가로 `output/qa/jev_api_calls/`의 영속 예약을 공유한다. 같은 요청은 재시작 후에도 거부하고 UTC 날짜 기준 최대8회(실패 포함)만 허용한다. 이 증거 디렉터리는 삭제하지 않는다. 타임아웃처럼 과금 여부가 불명확하면 먼저 해당 시도 보고서를 확인해야 한다. 입력을 바꾸면 별도 요청으로 간주되어 호출 한도를 하나 더 쓰며, 재시작하면 세션 상한만 초기화되며 영속 중복 차단과 일일 상한은 유지된다. 독립적인 `--live` CLI 실행도 같은 영속 중복 차단·일일 상한을 따른다. 매크로 실패는 세션 실패로 처리한다.

게임 호출 기록은 `temp/jev_YYYY-MM-DD/capture_choice_<frame>_<ns>.json`에 요청 전에 `request_started`, API/응답 오류 시 `api_or_response_error`, 검증 성공 시 `choice_recorded`로 보존한다. 성공 응답의 `usage`/`model`을 기록하고, 응답 검증 실패라도 형식이 유효한 사용량/모델은 남긴다. 파일이 `request_started`에 머물면 API 과금 여부가 불확실한 상태로 보고 재호출하지 않는다. 청구 여부가 확인될 때까지 이 미완료 시도 보고서를 삭제하지 않는다. `actions.jsonl`의 `jev_rejected`에는 시도 보고서 경로가 연결된다. API 호출·응답 검증 뒤 디스크 기록에 실패하면 결과 기록이 불완전할 수 있다.

`tools/jev_game_choice.py --live`도 요청 전에 로컬 보고서와 영속 예약을 fsync한다. 호출·응답 검증 오류에 `api_or_response_error`와 유효한 사용량을 남기고, 성공은 `choice_recorded`로 기록한다. 예약 단계의 거부는 `request_rejected`로 남으며 네트워크 호출이 없다. 보고서가 이미 있으면 덮어쓰지 않고 새 호출을 거부한다.

게임 경로의 API 요청에는 후보 문맥과 ROM·체크포인트·프레임 SHA-256, 프레임 번호가 들어간다. ROM/세이브 원본 바이트와 스크린샷 파일은 보내지 않는다. 이는 번역 분류 경로(완결 문구만 선택)와 별도로 적용한다.

네트워크 없는 게임 선택 회귀 검사는 다음과 같이 실행한다.

```sh
python3 -m unittest discover -s tools -p test_jev_game_choice.py -v
```

이 연결은 JSON을 준비하는 Codex의 반복 해석·API 호출·입력 지시 왕복을 줄일 수 있지만, 현재 상태 구조화와 후보 작성을 자동화하지는 않는다. 그러므로 “Codex 토큰 절감 달성” 수치를 주장할 근거는 아직 없다. 토큰을 더 줄이려면 관측된 기록에서 공개 게임 상태와 합법 후보를 로컬 생성하고, 상태 변화가 있는 결정 지점에서만 질의해야 한다. 실행기는 외부 API 응답을 게임 코드로 취급하지 않으며, JEV 선택을 승률/전략 성공 보증으로 보지 않는다.

## 설정과 실행

- 공식 API: `https://api.typesafe.ai`, 인증: 환경변수 `JEV_API_KEY`를 Bearer 헤더로 사용.
- 키는 사용자가 설정한 `.zshenv`/`.zshrc`에서 상속한다. 스크립트는 이 파일들을 읽거나 수정하지 않는다. 키를 인수·설정 파일·로그에 넣지 않는다.
- [config/jev.json](../config/jev.json): `jev-latest`, 검토 경계 0.3/0.7. 계정 모델 조회 결과 `jev-latest`, `jev-preview`가 있었으며, 실험 버전은 선택하지 않았다. alias는 바뀔 수 있으므로 보고서에 실제 응답 모델도 기록한다.
- Python 3.9 이상. macOS python.org Python의 인증서 문제는 `python3 -m pip install -r tools/requirements-jev.txt`로 CA 번들을 설치해 해결한다. 현재 컴퓨터에는 이미 설치되어 있다. TLS 검증을 끄지 않는다.

프로젝트 루트에서 실행한다:

```sh
# 인증된 모델 목록 조회 (네트워크 GET)
python3 tools/jev_triage.py --models

# 기본값은 로컬 준비만. API 요청 0회
python3 tools/jev_triage.py --input tools/fixtures/jev_semantic_smoke.json

# 선택한 예제만 1회 전송. 보고서 이름은 매번 새로 지정
python3 tools/jev_triage.py --input tools/fixtures/jev_semantic_smoke.json \
  --live --output temp/jev_trial/result.json

# 네트워크 없는 회귀 검사
python3 -m unittest discover -s tools -p test_jev_triage.py -v
```

입력은 JSON 배열이다. 한 번에 1~8개의 완결 메시지만 사람이 선별한다. `id`는 답을 암시하지 않는 ASCII 식별자, `ja`/`ko`는 원문/번역, 선택적 `context`는 인물·상황·분리된 조각의 연결 정보다. ROM·저장 파일·스크린샷·전체 저장소는 전송하지 않는다. `expected_error` 등 다른 필드는 API에서 제외한다.

```json
[{"id":"case01","ja":"この橋を渡ってはいけない。","ko":"이 다리를 건너면 안 된다.","context":"진행 금지 경고의 완결 문장"}]
```

입력 파일과 전체 요청은 각각64KiB 이하, 텍스트 필드당4,000자 이하이다. 실행 1회당 단일 요청·소켓 작업별30초 타임아웃·자동 재시도 없음으로 요청량을 제한한다. 번역 분류 경로에는 반복 실행의 일일/계정 한도나 전체 경과시간 제한이 없다. 앞의 게임 선택 경로에 적용한 UTC 일일8회 영속 상한과 별개다. API HTTP 오류 본문과 인증 헤더는 출력하지 않고, 리다이렉트도 거부한다. 보고서는 새 `temp/` 파일로만 작성한다. 일반 빌드·편집기·배포 게이트에서는 호출하지 않는다. 사용자 요청 범위에서 선별한 일본어·한국어 문구와 문맥이 제3자 TypeSafe API로 전송된다. 제공자의 보관·학습 정책은 이번 연결 시험에서 검증하지 않았으므로 별도 기밀 문서는 입력하지 않는다. 응답 검증이나 디스크 기록 실패 시 이미 과금된 호출의 결과가 남지 않을 수 있으며 자동 재요청하지 않는다.

## 결과 해석

`semantic_error_probability`는 JEV가 답한 의미 오류 확률이다. 프로젝트에서 정확도/확률 보정이 검증된 수치가 아니다.

| 범위 | 표시 | 처리 |
|---|---|---|
| 0.7 이상 | `review_first` | 먼저 원문과 실제 조립 대사를 검토 |
| 0.3 초과, 0.7 미만 | `uncertain_review` | 애매한 후보로 유지, 자동 제외 금지 |
| 0.3 이하 | `lower_priority` | 우선순위만 낮춤. 오류 없음/승인 아님 |

임계값은 운영 초깃값이고 이 소수 예제로 최적화하지 않았다. 번역문 안의 지시문을 모델이 따르거나 여러 예제가 서로 영향을 줄 가능성도 있어, 결과는 비신뢰 분류 정보로만 취급한다. 질문 ID·타입·유한한0~1확률·사용량 형식은 클라이언트가 다시 검사하며, 실패하면 종료코드2로 중단한다.

## 소규모 시험 결과

증거: `temp/jev_2026-09-30/`. 공식 스키마, 모델 조회, 요청별 결과와 실제 대사의 원본/수정ROM 식별을 보존했다. 실제 인증 키는 기록하지 않았다.

- 최종 합성8개(`smoke_balanced.json`): 부정·숫자·지역명 누락·소유관계의 오류/정상 쌍. 쌍별 문맥을 동일하게 맞추고 불투명 ID와 섞인 순서로 시험했다. 오류4개는0.94~0.98, 정상4개는0.05~0.09. 1,889입력토큰/148출력토큰, 약0.967초. 같은 요청 안의 대조 예제이므로 독립적인 정확도 평가는 아니다.
- 실제2메시지의 수정 전후4개(`project_result.json`): A0F164 소유관계(r01→r02)와 A0F328 금지명령 조립(r03→r04). 표시 제어 마커를 공백으로 바꾼 텍스트이며 원본/수정ROM은 `project_provenance.json` 참조. 수정 전0.56/0.53 → 수정 후0.16/0.26. 한 요청 안에서 비교한 참고 관측이고 실화면/최종ROM 검증이 아니다. 알려진 오류도 `review_first`까지 올라가지 않았으므로 확정오류 판정이나 저확률 자동승인에 사용하면 안 된다. 1,208입력토큰/76출력토큰, 약1.825초.
- 최초 합성 시험은 ID가 오류/정상 여부를 암시했고, 두 번째 시험에도 지역명 오류 행만 추가 문맥이 있었다. 두 결과는 품질 근거에서 제외하고 마지막 시험에서 ID·문맥·순서를 보정했다. 이전3개 보고서의 `canonical_payload_sha256`은 정규 직렬화 해시이며 전송 바이트 해시가 아니었다. 클라이언트를 보강한 최종 시험부터 `request_sha256`이 실제 전송 바이트와 일치한다.
- 실제 과금 대상 추론은 총4회, 입력6,895토큰/출력514토큰. 공개 단가 $0.042/백만 입력토큰과 출력 무료 기준 추정 약 **$0.00029**다. 청구서 확인값은 아니며 가격은 변경될 수 있다. 무료 크레딧 여부도 확인하지 않았다.

선택된12개 비교로 프로젝트 전체 정확도나 다른 언어/화자/분기 성능을 주장하지 않는다. 다음 활용은 이미 추출·조립·소유권이 확인된 소규모 후보를 분류하고, 실제 검수 결과와 오탐/누락을 따로 쌓는 것이다.

## 공식 참고

- [API 문서](https://api.typesafe.ai/docs), [OpenAPI 스키마](https://api.typesafe.ai/openapi.json): GET `/v1/models`, POST `/v1/systemone`, `state/model/questions`, `noul/choice/score` 응답.
- [JEV 소개와 가격 설명](https://typesafe.ai/blog/introducing-system-one-models-and-jev): 구조화된 판단 용도와 공개 입력 단가. 제공자의 정확성 홍보 문구를 게임 검증 보장으로 취급하지 않는다.

검토: 번역 분류 연결에 대한 이전 회귀/리뷰 기록이다. 게임 선택 경로에는 별도 회귀와 Claude 적대 검토를 적용했다. 이는 API 분류 품질이나 게임 전체 검증의 승인이 아니다.

게임 영속 원장은 새 연결의 게임 선택 호출만 기록하며 번역 분류 호출이나 계정 청구서 전체를 대신하지 않는다. 기존 파일럿 호출은 과거 보고서에 별도로 남는다. 원장이 손상되면 새 호출을 거부한다. 과금 불확실 기록은 공급자 청구·요청 상태와 대조하여 별도 근거로 보존하고 임의 삭제나 자동 재시도를 하지 않는다.
