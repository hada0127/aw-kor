## 배치 수정의 보존 조건

`data/dialogue_layout_repairs.json`에는 검토한 메시지별 원래 바이트 SHA, 전/후 행, 창 프로필이 있다. 빌더의 마지막 텍스트 단계에서 적용하고 이후 동일 픽셀 검사를 실행한다. 포인터, 할당 길이, 비배치 제어, 단어·부호 순서는 유지한다. 원래 공간을 넘는 새 페이지를 위해 인접 데이터를 침범하지 않는다.

줄을 나눈 소스 행은 `source_line_fragments`로 실제 조각을 기록한다. `source_fragment_joiners`의 빈 문자열/8140이 문장부호 경계와 단어 경계를 구분한다. B팀 검사는 첫 조각만 읽지 않고 전체 소스 행을 복원해 비교하며, 각 실제 행은 별도로 폭을 검사한다. 기준 B팀 파일을 새 ROM에 맞춰 재설정하지 않는다.

별도로 확인한 비B팀 소스 교정은 중복 `면`, `요새을`, `자주포을 그그냥`의 조각 이음 오류와 같은 의미의 음식 선호 문장이다. 전/후 원장은 별도 증거 폴더에 둔다.

## 범위가 다른 증거

자동 검사의 PASS는 모든 정상 플레이 경로를 실행했다는 뜻이 아니다. 정적 소비자 검사, 정상 cold boot/키 입력, QA 카트리지 저장으로 시작한 실행, RAM을 고친 강제 실행을 각각 구분한다. 외부 save의 치트 오염을 지우거나 savestate를 정상 해금 근거로 쓰지 않는다.

UI·사전·입력 변환 테이블과 포인터 없는 추출 문구는 별도 원장으로 남긴다. 양의 소비 근거가 없는 초안 추정 구간을 단순히 '미사용'으로 지우지 않는다. 미검증 소비자/화면은 후보 보고서의 미검증 목록에 명시한다. 완료 여부와 최종 설치 상태는 후보 증거 및 Mac 설치 영수증으로 판단한다.
