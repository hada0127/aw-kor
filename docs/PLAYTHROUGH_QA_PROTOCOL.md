# 1·2편 전 구간 한글 화면 검수 절차

## 적용 범위

1편과 2편의 정상 패드 입력 플레이, 대사·메뉴·전투·장면 전환의 전 프레임 보존에 사용한다.
실제 도달 범위와 현재 작업은 `todo.md`, ROM 및 입력·프레임 증거는 각 run 디렉터리를 기준으로 한다.
**캡처 성공과 시각 검수 완료는 별도 판정**이다. 이 절차 자체가 캠페인·엔딩·분기 검수 완료를 뜻하지 않는다.

- 수정 전 기준 ROM: 실행 당시 `output/game_wars_korean_full.gba` (각 run 디렉터리에 동결 복사)

- 실행 시작 당시 full/final/title_test 3종 동일 해시. 실행 시작마다 별도 복사하고 다시 해시를 확인했다.
- 시작 당시 git HEAD: `6fc6085b03bc5193fdbde25963f478f5ea84f5ac`. 기존 미커밋 번역/문서 수정이 있어 현재 소스와 이 ROM의 일치는 주장하지 않는다.
- 사용자가 방식 선택을 위임함에 따라 OS Computer Use 대신 mGBA 코어의 화면 관찰과 정상 패드 입력을 사용했다.
- 설치 확인: mGBA 0.10.5, FFmpeg/ffprobe 8.1.1, OBS.app, emucap/Mesen 어댑터. 추가 설치 없음.

## 도구 역할과 근거
1. mGBA: GBA 실행, Lua 프레임 완료 콜백, 원해상도 스크린샷, 세이브스테이트. https://mgba.io/docs/scripting.html
2. emucap: 실제 화면 관찰, 패드 입력, pause/step, 장면별 스크린샷. 현재 어댑터의 status.methods를 확인해야 한다. MCP screenshot만 간헐적으로 호출해서는 애니메이션 전 프레임을 보존할 수 없다.
3. FFmpeg/ffprobe: 무손실 FFV1 보존, PNG 추출, 디코딩 및 프레임 수 확인. https://github.com/FFmpeg/FFV1 https://ffmpeg.org/ffmpeg.html
4. OBS: macOS 창 녹화 보조 증거. 화면 녹화 권한과 캡처 설정은 실제 확인 필요. https://obsproject.com/kb/macos-screen-capture-source
5. 기존 tools/auto_playthrough.py: 반복 입력과 축소 회색조 화면 차이로 샘플 수집. 전투 전략/엔딩 도달 및 전 장면 검수의 근거로 사용 불가. 40프레임 간격과 유사도 필터는 짧은 애니메이션/작은 글리프 결함을 누락할 수 있다.

## 실행 절차
1. 기준 ROM을 검사 디렉터리에 복사하고 해시를 고정한다. 기존 사용자 SRAM과 세이브를 덮어쓰지 않는다. 별도 새 저장 데이터로 콜드부트한다.
2. 게임 첫 프레임 이전에 캡처를 준비한다. 프레임 완료 콜백 또는 코어 녹화로 매 프레임 원해상도 240×160 RGB를 무손실 보존한다. OBS의 60fps 녹화만으로 GBA 내부 프레임 누락 0을 선언하지 않는다.
3. 첫 짧은 구간에서 내부 프레임 번호, 저장 성공 수, 영상 디코딩 프레임 수를 대조한다. 저장 오류/프레임 공백 시 해당 구간을 미검증으로 표시하고 직전 체크포인트에서 재수집한다.
4. 1편을 선택하고 튜토리얼부터 캠페인 엔딩까지 화면을 관찰하며 정상 입력으로 진행한다. 대사 페이지가 완성된 것을 보고 다음 입력을 보낸다. 전투 애니메이션을 켜고 빠른 진행/스킵은 사용하지 않는다.
5. 각 대사 페이지, 선택지, 임무 소개, 일수 전환, 전투/점령/합류/수송/보급, CO 파워, 승리/패배/평가, 저장/로드, 엔딩/크레딧을 장면 원장에 기록한다. 게임에 실제 존재/도달한 항목만 관측으로 표시한다.
6. 분기·다른 선택·패배 경로·숨겨진 임무 등은 별도 경로 목록으로 남긴다. 단일 엔딩 도달은 모든 장면 확인과 구별한다. 원본/스크립트/게임 경로로 모집단을 확정하기 전 전수 완료율을 만들지 않는다.
7. 매 임무 시작/종료에서 저장 상태와 입력 로그를 남긴다. 상태는 ROM 해시/에뮬레이터 버전에 묶는다. 플레이 중 메모리 조작으로 승리를 강제하지 않는다.
8. 글자 깨짐, 획 손실, 잘림, 겹침, 공백 손실, 이전 글자 잔상, 일본어 잔존, 초상/유닛 손상을 검사한다. 애니메이션은 연속 영상과 전환 전후 프레임을 확인한다. 축소 연락시트/OCR은 후보 탐색만 하며 통과 판정은 원해상도/정수배 확대 화면으로 한다.
9. 의심 장면은 ROM 해시, 임무/턴/대사, 프레임 범위, PNG/영상/상태/입력 경로, 관측 내용, 원본 비교 여부를 기록한다. 불명확하면 판정 보류한다.
10. 완료 조건은 모든 예정 경로 도달, 캡처 연속성 확인, 장면 원장 전체 검수 완료, 미해결 결함/미검증 범위 명시다. 캡처 수와 검수 수는 별도 집계한다.

## 실행 방법

아래 명령은 저장소 루트에서 실행한다. 모든 실행 디렉터리는 새 이름을 사용해야 한다.

```sh
mkdir -p temp/part1_capture
clang -I/opt/homebrew/include tools/mgba_harness.c -L/opt/homebrew/lib -lmgba -o temp/part1_capture/mgbah
python3 tools/playthrough_capture.py --rom output/game_wars_korean_full.gba --harness temp/part1_capture/mgbah --out output/qa/part1_new_run
```

대화형 입력 예:

```text
NONE 480
START 180
A 240
note 이름 입력 화면 확인; 시각 검수는 부분 완료
quit
```

- `KEY N`: 해당 버튼을 2프레임 누르고, 뗀 채 N프레임 진행. `NONE N`은 입력 없이 N프레임 진행. N은 1~1800.
- 사용 가능한 키: A, B, SELECT, START, RIGHT, LEFT, UP, DOWN, R, L.
- 다음 명령은 화면을 본 뒤 결정한다. 대사 완료 표시가 없으면 `NONE`으로 기다린다.
- 동시 키/장시간 누르기는 현재 지원하지 않는다. 반복 방향 이동은 개별 탭을 기록한다.
- 게임 진행은 명령을 보낸 동안에만 일어난다. 에이전트가 이미지를 읽는 동안에는 정지 상태다.
- 매 프레임 내부 코어 카운터 +1을 확인하고 240×160 RGB PNG를 저장한다. 동일 RGB는 PNG 파일을 공유하지만 원장에는 모든 프레임이 남는다.
- PNG를 다시 열어 RGB SHA256을 대조한다. 연락시트는 검수 보조용 샘플이므로 전체 프레임을 대신하지 않는다.
- CLI PNG 압축 기본값은3이며 `--png-compress-level 6`으로 디스크 용량을 줄일 수 있다. 프로그램 호출에서 인자가 없으면 기존6이다. 선택값은 baseline에 기록한다. 압축 변경은 RGB·프레임 원장·체크포인트 검증을 바꾸지 않는다. [측정 범위](reports/CONTINUATION_2026-09-30.md).
- 초기 상태는 아직 완성된 프레임이 없는 core frame 0이다. 실제 완료된 첫 프레임 1부터 수집한다.
- 저장공간을 매 프레임 확인한다. 기본 여유 공간 하한 10GiB 미만이면 다음 프레임 전에 중단한다. `--min-free-gib`으로 설정 가능.
- 명령별 제한 시간은 기본 10초. 캡처 실패 후 상태를 정상 재개 지점으로 발행하지 않는다. 타임아웃·응답 불일치·추가 응답이 있으면 이후 프로토콜 명령을 보내지 않고 자기 에뮬레이터 프로세스만 정리한다. 매 shot 전에 이전 raw를 지워 저장 실패가 이전 프레임으로 위장하지 못하게 한다.
- 정상 체크포인트는 PNG/원장/상태 파일의 저장을 동기화한 후 발행한다. 손상은 재개 시 다시 검증하며, 전원 장애에 대한 별도 실기 시험은 하지 않았다.

재개:

python3 tools/playthrough_capture.py --rom output/qa/part1_2026-09-15/run02/baseline.gba --harness temp/part1_playthrough_2026-09-15/mgbah_capture --out output/qa/part1_2026-09-15/run03 --resume output/qa/part1_2026-09-15/run02/resume.checkpoint.json

`run02/0159_A_0039150.checkpoint.json`을 별도 실행으로 재개하는 편이 적절하다.
ROM/하네스/libmgba 해시가 바뀌면 재개를 거부한다. 수집기 소스 해시는 실행별 출처 기록이며 동일 버전 강제 조건은 아니다. 같은 캡처 의미를 유지하는 변경에 한해 재개한다. 수정 ROM은 새 콜드부트/입력 재생으로 검증한다.

## UI 에디터 저장과 빌드 적용 검증

- 실제 수정은 대사맵·조립그룹·대사 override·해당 보호 TSV를 하나의 저장 묶음으로 갱신한다. 변경 없는 보호 TSV 표시값을 다른 원문 번역 위에 덮어쓰지 않는다.
- 변경 없는 일반 문구는 기본 저장에서 파일을 바꾸지 않는다. `현재 문구 그대로 적용`을 선택하면 기존 자동 공백 보정보다 현재 문구를 우선하는 적용 의도를 명시한다. B팀과 보호 TSV는 이 확정 대상에서 제외한다.
- 적용 의도는 `data/editor_override_intents.json`에 주소와 문구의 SHA-256으로 저장한다. 정확히 같은 문구에만 유효하며, 의도를 취소하려면 해당 기록을 제거한다. 번역과 함께 버전 관리한다. 빌드는 전체/불일치 기록 수를 출력한다.
- 좁은 표시 영역용 `display_overrides.json` 항목은 실제 표시값을 보여 주되 일반 대사 편집에서 읽기 전용이다. 글리프 등록 사전과 병합 문장의 하위 조각도 일반 대사로 저장하지 않는다.
- 일반 대사의 빈 값은 거부한다. 보호 행의 명시적 비우기는 TSV의 빈 값과 직접 스크립트의 빈 payload를 구분해 적용하며, 재배치가 옛 문구를 되살리지 않는지 검사한다.
- `saved`는 실제 문구 수정, `confirmed`는 기존 문구의 적용 확정, `unchanged`는 파일 변경 없음이다. 성공 응답만으로 ROM 적용을 판단하지 않는다.
- 검증은 격리 복사본에서 브라우저 조작 → 저장 파일 비교 → 원본 ROM 기반 전체 빌드 → 실제 메시지 포인터와 바이트 확인 → 정상 입력 화면 재생 순으로 수행한다. QA 도구가 저장 전후 되돌릴 때는 적용 의도와 보호 TSV·조립그룹도 포함한다.
- 행 보기/조립 보기 전환은 숨긴 뷰의 실제 `display`와 스크린샷으로 확인한다. `[hidden]`이 flex 스타일에 덮여 두 뷰가 동시에 표시되지 않아야 한다.

## 누르는 시간 지정 (2026-09-22)

`playthrough_capture.py`는 `KEY RELEASE_FRAMES [HOLD_FRAMES]`를 받는다. 기존 두 인자 입력은 버튼 2프레임/NONE 0프레임 그대로이며, 선택 인자는 버튼 1..120프레임(NONE은0만)을 허용한다. 해제 시간은1..1800이다. 예: `RIGHT 180 12`, `A 600 6`. 매 hold/release 프레임과 입력 비트가 원장에 남으며, replay/export도 같은 시간을 보존한다. 이는 일반 패드 입력 길이 조정이며 RAM/승리조건 조작이 아니다.

### 2026-10-06 사용자 결정: 증거 체인 절단(anchored 정상 저장)

`output/qa`의 전 프레임 증거(~65GB) 체인을 끊고 핵심 기록만 남기기로 했다. 닫힌 옛 run의 대량 frames는 이후 삭제될 수 있으므로, 새 실행은 조상 프레임 재검증에 의존하지 않는다.

- 내보내기: `python3 tools/game_save_evidence.py --anchored --reason "<사유>" --checkpoint <run>/<tag>.checkpoint.json --harness <mgbah> --out <새 디렉터리>` → `<새 디렉터리>/game_save.json` (kind `cartridge-save-anchored-v1`). 기본은 내보낼 때 원본 체인 전체를 검증한다. frames가 이미 정리된 run은 `--skip-source-frame-check`로 체크포인트 ROM/상태/baseline/하네스/libmgba만 검증하며, 이 사실을 receipt의 `source_chain_verification`에 남긴다. 하네스는 원본 체크포인트와 같은 SHA여야 한다.
- 새 실행: `python3 tools/playthrough_capture.py --rom <ROM> --harness <같은 mgbah> --out <새 run> --game-save <새 디렉터리>/game_save.json`. 콜드부트 frame0에서 저장 바이트를 대조하고 새 체인 루트가 된다. 이 run의 `--resume`은 이 run의 로컬 저장/receipt 사본까지만 검증하며 원본 run을 열지 않는다. 호환 ROM 이관은 기존 `--game-save-source-rom-sha256`을 사용하고, 저장 형식은 receipt에 기록된 `save_storage`와 대조한다.
- 검증 범위: receipt 필드, 저장 크기/SHA/균일값 아님, 대상 ROM SHA(또는 선언한 이관 원본 SHA), 하네스·libmgba SHA. `source_checkpoint`·`source_core_frame` 등은 참고 정보이며 재검증하지 않는다. 즉 anchored 이전 구간의 프레임 증거는 이 receipt로 대신하지 않는다.
- 기존 `cartridge-save-from-recorded-checkpoint-v1` receipt와 `--export-game-save`는 동작이 바뀌지 않으며 계속 원본 체인을 검증한다.
