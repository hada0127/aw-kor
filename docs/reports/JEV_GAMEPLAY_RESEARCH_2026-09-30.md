# JEV 자동 진행·한글화 커뮤니티 조사

조사일: 2026-09-30. 최초 조사는 공개 자료와 연결 가능성을 검토했다. 사용자 요청에 따라 이후 안전 제한 연결과 실제 게임 파일럿을 진행했다. 최신 지시에 따라 Codex 사용률은 중단 기준으로 사용하지 않고 RAM·디스크 여유만 감시한다.

## 파일럿 후속 및 절약 효과

초기 문서 작성 후 `tools/jev_game_choice.py`와 `tools/playthrough_capture.py`의 `jev temp/...json` 경로를 구현했다. 현재 입력 파일은 네 가지 증거 필드(ROM 해시, 프레임 번호, 체크포인트 해시, 마지막 프레임 해시)에 묶인다. JEV에는 문맥·목표·후보 의미만 전달되고, 후보 ID 외의 응답은 허용하지 않는다. 선택 확률 합·선택 여유·confidence를 확인한다. 실행 매크로는 로컬 JSON의 최대8단계/480프레임 방향키/NONE 이동으로 제한된다. inspect는 선택 확률·confidence 모두0.5, commit은0.7 기준이나 화면 기반 합법성 검증기가 없어 commit은 자동 입력하지 않는다. 이는 보정된 안전/정확도 수치가 아니라 초기 파일럿 정책이다.

이전 수동 확인 단계에서 JEV가 공격 후보를 골랐고, 사람이 화면을 확인하고 실행한 뒤 로켓이 대공 유닛을 파괴하고 HP10을 유지한 한 차례를 기록했다. 이 행동은 새 제한 매크로가 실행한 것이 아니며, 좁은 상황의 후보 선택 관측일 뿐 자동 진행 성능 증거가 아니다. 기존의 잘못 짝지은 ROM/세이브 캡처는 유효한 플레이 증거에서 제외했고, 그로 인해 저장 데이터의 대상 ROM 해시 일치 검사를 추가했다. 자세한 프레임별 사실과 체크포인트는 `temp/jev_2026-09-30/`에 보존했다.

토큰 절약 관점에서, 기존 수동 루프는 Codex가 매번 화면을 해석하고 요청·입력을 만들었으므로 JEV API 토큰만 절약했을 뿐 Codex 토큰을 줄였다고 입증할 수 없다. 새 `jev` 명령은 정확한 캡처 증거 확인, JEV 호출, ID 검증, 사전 등록한 안전한 inspect 매크로 입력을 한 로컬 호출로 묶어 이 반복 왕복을 줄인다. 다만 상태 JSON과 후보는 여전히 사람이/Codex가 작성한다. 완전 자동 상태 추출·합법 후보 생성기는 아직 없다. Codex 토큰 절약량이나 선택 품질의 수치 주장은 하지 않는다.

로컬 검증: `test_jev_game_choice.py` 17개, `test_jev_triage.py` 11개, `test_game_save_evidence.py` 12개, 주간 사용량 검사기 9개 통과; 관련 Python 파일 컴파일 성공. 이 보고서의 최초 계획은 구현 전 상태를 반영하므로, 위에서 구현 완료 범위를 최신화했다.

리뷰: 직전 Claude 적대 검토는 블로커 없음이었고, 지적된 운영 안내·테스트 수 오기를 반영했다. 후속 보강은 읽을 수 없는 입력을 복구 가능한 입력 오류로 분류하고 손상된 프레임 ledger를 치명 오류로 중단하도록 했다. 앞선 `--bare` 호출의 인증 실패는 실행 옵션 문제였으며, 일반 OAuth 로그인으로 후속 Claude 읽기 전용 리뷰를 완료했다. 키 검사 전 영속 예약 등의 유효 지적을 수정하고 2026-09-30 최종 후속 검토에서 확정 blocker 없음이 확인됐다. agy는 사용자 지시로 폐기했다.

참고 파이프라인: [arqhive/game-korean-localization-pipeline](https://github.com/arqhive/game-korean-localization-pipeline), revision [`fcfb415`](https://github.com/arqhive/game-korean-localization-pipeline/tree/fcfb4158409990490ea5ccd8596aa91c5f125dd5). 분야 적용성, 무변경 왕복, 안정 ID/용어집, 그래픽 비교 시트, 추출 범위와 회귀/배포 분리 원칙을 대조했다. 기존 GBA 도구와 중복되는 프로세스는 복제하지 않았고 대응표는 [`LOCALIZATION_GATES.md`](../LOCALIZATION_GATES.md)에 기록했다.

## 결론과 확인 근거

JEV를 자동 진행의 행동 선택기로 사용할 수 있다. TypeSafe의 [공식 Doom 데모 설명](https://typesafe.ai/blog/introducing-system-one-models-and-jev)은 이미지 대신 텍스트를 포함한 구조화된 게임 상태를 사용한다고 명시한다. 동시에 일반 봇이 더 잘 플레이할 수 있다고 인정한다. 따라서 게임 연결 가능성의 근거이지 우리 게임의 승률·완주 성능 증명은 아니다.

[공식 API 스키마](https://api.typesafe.ai/openapi.json)의 `choice` 질문으로 미리 정의한 후보 중 하나를 선택하게 할 수 있다. 현재 `tools/jev_game_choice.py`가 제한된 게임 선택을 지원한다. 이전 연결 시험의 성공을 자동 플레이 성공으로 간주하지 않는다.

## 전체 자동 진행을 위한 남은 적용 제안

관측 상태 → 로컬 합법 행동 생성 → JEV의 행동 ID 선택 → 기존 하네스 입력 → 결과 관측·검증 순서로 구성한다.

- 관측: 아군, 공개된 적, 관측한 지형, 자금, 커서, UI 단계와 임무 목표를 구조화한다. 숨겨진 적 정보를 읽지 않는다. 화면 좌표와 지도 좌표를 분리한다.
- 후보 생성: 이동 경로·공격 사거리·생산 비용 등은 로컬 규칙으로 검사한다. JEV에 임의 버튼열을 생성시키지 않는다. 임무별 전략 목표와 최근 진행 내역을 후보 판단 문맥에 포함한다.
- 실행: 응답의 ID가 실제 후보인지 검증하고, 상태가 달라졌으면 폐기한다. 선택 유닛·커서·자금·대상을 확인한 뒤 제한된 입력만 보낸다.
- 검증: 기대한 상태 전환이 발생했는지 확인한다. 알 수 없는 화면, 반복 행동, 장기 정체, 예상 밖 손실, API 예산 소진 시 해당 자동 실행을 중단하고 근거를 남긴다. 모델 confidence를 승리 확률로 해석하지 않는다.
- 자원: 에뮬레이터 1개로 시작한다. 대사 넘김·메뉴 이동은 검증된 규칙으로 처리하고 JEV는 전술 결정 지점에서만 호출한다. 모든 프레임의 기록 및 동일 이미지 중복 제거 규칙은 유지한다. 로컬 대형 모델은 필요하지 않지만 캡처·인코딩의 부하는 별도로 측정한다.

현재 `tools/playthrough_capture.py`에는 제한된 키 입력, 프레임 기록, 체크포인트 검증 기반이 있다. `temp/part1_2026-09-28/recorded_state.py`는 확정된 기록 상태를 읽는 기존 보조 도구다. 이 기반만으로 합법 행동 생성이나 전략 판단까지 구현되어 있는 것은 아니다.

## 효율적인 도입 순서

1. 기존에 관측한 상태로 입력·합법 후보·응답 검증기를 만들고 실제 입력 없는 판단 시험을 한다. 같은 상태의 간단한 규칙 기반 선택과 비교한다.
2. 메뉴·커서·짧은 이동만 연결해 상태 불일치와 좌표 오인을 검출한다.
3. 목표와 성공 경로가 알려진 임무 하나를 시험한다. 불법 선택 수, 반복·정체 수, 목표 진행, 턴 수, 손실, API 비용, 추가로 도달한 화면을 기록한다.
4. 위 결과가 규칙 기반 진행보다 도움이 될 때 임무를 확대한다. 한 임무 성공을 1·2편 전체 완주 가능성으로 일반화하지 않는다.

자동 진행은 검수 장면 확보 비용을 줄이는 수단이다. 엔딩 도달만으로 번역·스프라이트·분기 화면의 무결성을 승인하지 않는다. 실제 화면 검수와 정적 검사는 기존 `docs/PLAYTHROUGH_QA_PROTOCOL.md` 기준으로 별도 유지한다.

2026-09-30 후속: 사용자 확인과 `claude auth status`로 일반 OAuth 로그인을 확인했다. 앞선 `--bare` 호출은 OAuth를 사용하지 않은 실행 방식 오류였으며 현재 인증 실패로 해석하지 않는다. 일반 로그인/Read·Grep 한정 Claude 리뷰가 실제 완료됐다. agy는 사용자 지시로 현행 리뷰 설정에서 폐기했다. JEV의 새 게임 호출에는 CLI/Recorder 공통 UTC 일일8회 영속 예약·재시작 후 중복 거부·실패 사용량 기록을 추가했다. 정상 SRAM 이관은 출처 SHA를 명시하는 별도 옵션으로 보존한다.
