# 1편 메뉴 스프라이트 원본 스타일 재작업

## 범위

사용자 후속 요청: 흰 테두리와 그림자 순서, ㄹ/ㅌ 가독성, 작은 제목의 원본 그라데이션,
하단 영어 유지. 대상은 1편 메뉴 컨테이너 33개(큰 옵션 15, 작은 제목 18)다.
전체 게임 스프라이트 수정 완료나 배포 승인 보고서가 아니다.

- 비교: `../screenshots/sprite_style_2026-09-07_revision2/index.html`
- 왼쪽 원본, 가운데 직전 후보, 오른쪽 이번 후보. 1배/3배 자산 비교와 2배 실화면 비교를 구분한다.
- 자연 경로 27개 캡처에서 10개 자산 관측, 23개 미관측. 관측은 OAM/VRAM 대응이며
  반복 캡처 수를 자산 또는 전체 플레이 검증 수로 계산하지 않는다.

## 원본 근거와 수정

큰 메뉴는 원본의 어두운 윤곽(14)과 1px 우하단 그림자(9)를 흰 외측 테두리(10)가 감싼다.
표시될 윤곽과 그림자의 이진 마스크 합집합에서 외측 테두리를 만들어 경계의 끊김을 막았다.
몸체의 6→1→6 그라데이션은 유지한다.

작은 제목은 구조가 다르다. 원본 C18F48 등의 상단 몸체가 흰색(10)이고 하단이 1→7이며,
윤곽은 14, 그림자는 9다. 큰 메뉴와 달리 그림자 밖 흰 테두리를 추가하지 않는다.
흰 몸체 AA에는 회색 12, 유색 하단 AA에는 8을 사용한다. ROM 팔레트 데이터는 수정하지 않고 타일 인덱스만 변경했다.

영어는 원본 ROM에서 복원한다. 4개 짧은 제목(C1A81C/C1AC60/C1B3A8/C1B610)은 y19,
나머지는 y24부터 시작한다. 영어 아래 여섯 행에서 가로 범위를 구해 일본어 제목 잔재를 제외한다.
겹친 일본어 그림자(9)는 제거하되, 영어 윗테두리의 양쪽 14 사이를 덮은 그림자 6px는 14로 복원한다.
복원 위치: C194D8 x28/29, C19D14 x24/34, C19FF0 x34, C1A2BC x30(모두 y24).
C1A9DC 영어의 원본 AA 인덱스 3도 보존한다.

기존 작은 제목 주소 설명도 원본과 달랐다. C1A81C는 RECORD/기록, C1B3A8은 CAMPAIGN/캠페인,
C1B610은 TRIAL/트라이얼이다. 텍스트 역조회 대신 주소를 전달해 같은 이름의 서로 다른 제목을 구분한다.
기록이 원본 448바이트 슬롯에 들어가므로 이전 후보의 AFF000 재배치는 사용하지 않는다.

NotoSansKR-Black으로 한글을 재렌더링하고 이전 OkDanDan 전용 고정좌표 보정은 제거했다.
`기록`/`작전룸` override는 256×16 타일 저장 격자 규약을 유지하면서 새 렌더 결과로 갱신했다.
다른 대사 또는 스프라이트 편집 데이터는 이 작업에서 변경하지 않았다.

## 재현과 검증

필요 폰트: `~/Library/Fonts/NotoSansKR-Black.otf`.
SHA256: `88ea5f1d54b29c49d36d8465b09181a1bdd8983877c4d781f0cd025b739cd5be`.
원본 ROM은 기존 프로젝트 원본이며 footer 추출 시 전체 SHA를 검사한다.

```sh
python3 tools/build_korean_full.py
python3 -m unittest discover -s tools -p 'test_sprite_*.py'
python3 tools/qa_visual_regions.py --harness temp/mgbah --action-menu-save ''
python3 tools/audit_sprite_override_report.py --strict
python3 tools/qa_text_fit.py
```

검증 내용: 단위 테스트 14개, 원본 슬롯 용량, 영어 보존/윗테두리 복원, 큰 메뉴의 외측 흰선,
넘침 거부, 편집기 저장 격자 왕복, OBJ 비표시 상태 제외, 기본 ROM 무결성 및 fresh-boot 실화면 QA.
비교시트 도구는 ROM SHA 및 캡처 파일(PNG/PAL/OAM/OBJ/DISPCNT) 해시를 확인하고 관측을 재계산한다.

전체 빌드와 비교용 후보의 SHA가 일치했으며 output full/final/title_test 3종을 동기화했다.
SHA256: `55db31de82aa6774884bd07e255539451a1cf538ef5eb6c396b7da20c1825ea0`.
`qa_visual_regions` 54개 검사 통과, `qa_text_fit` overflow 0, override 2개 적용/skip 0.
`qa_integrity_map --byte-only`는 388,547바이트 불일치 0으로 통과했다.
전체 `qa_integrity_map`는 문장부호 소실 2,449행, 중점 잔존(import) 400행으로 실패한다.
직전 후보에도 같은 맵으로 검사해 동일한 수치와 바이트 불일치 0을 확인했다.
이는 이번 스프라이트 변경으로 발생한 차이는 아니지만 배포 승인 문제로 남는다.

실화면 QA의 옛 경계 검사는 x80..86/y32..36의 이웃 메뉴를 제목 잘림으로 잘못 집계했다.
원본과 현재 OAM 24/25가 (0,0)64×32+(64,0)16×32임을 확인해 제목의 실제 80×32 안으로 제한했다.
이웃 메뉴 무시와 내부 경계 검출을 각각 테스트한다. 단순 색상 검사가 가독성 자체를 보증하지는 않는다.
세이브가 필요한 행동 메뉴/전체 전투 메뉴 검사는 이 실행에서 제외했다.

## 리뷰와 한계

Codex 독립 리뷰에서 footer 일본어 잔재, 외측 흰선 임계값 불일치, 중복 이름 주소 역조회,
검사 범위 문제를 확인하고 수정 후 재검토했다. 실제 제목 목록으로 용량 테스트도 보완했다.
Claude 초기 리뷰의 가정은 원본 실측으로 재검토했고, 유효한 API/넘침/타일 왕복 문제를 보완했다.
최종 후속 리뷰의 영어 테두리 6px 지적은 회귀 테스트와 함께 수정했다.
Codex가 18개 footer를 직전 알고리즘과 비교해 해당 6px만 변경됐음을 재확인했다.
agy는 재시도했으나 응답 시간 초과로 리뷰 결과를 받지 못했다.

미관측 23개 메뉴의 자연 경로 검증과 2편 결과 화면 등 다른 스프라이트는 미완료다.
배포 BPS/IPS와 배포 manifest는 이번 작업에서 갱신하지 않는다.
